# Supply Chain Control Tower

Демонстрационный дашборд для мониторинга ключевых показателей цепочки
поставок (ДУЦП БЕ Импорт, бренд X5 Import). Показывает 8 метрик по трём
разделам — Сервис, Логистика, Инфраструктура — в виде линейных графиков
(факт 2024–2026 + цель на 2026 год), с бейджами прогресса, hover-описаниями
методологии, детализацией по каждой метрике и экспортом в PDF.

Это прототип: все данные сгенерированы (mock) и не отражают реальные
показатели бизнеса.

## Технологии

| Слой | Инструмент |
|---|---|
| Фреймворк | [Next.js 16](https://nextjs.org) (App Router, TypeScript, React Server + Client Components) |
| Стили | [Tailwind CSS v4](https://tailwindcss.com) |
| UI-компоненты | [shadcn/ui](https://ui.shadcn.com) на примитивах [Base UI](https://base-ui.com) (стиль `base-nova`) |
| Графики | [Recharts](https://recharts.org), обёрнутый в `Chart`-компонент shadcn |
| Тема | [next-themes](https://github.com/pacocoursey/next-themes) — light/dark, тёмная по умолчанию |
| Иконки | [lucide-react](https://lucide.dev) |
| Шрифты | Фирменные X5 Sans / X5 Sans UI через `next/font/local` |

Node.js LTS, npm — единственный пакетный менеджер проекта.

## Архитектура

### Поток данных

```
data/mock-metrics.json          — сырые данные: 4 ряда (2024/2025/2026/Цель)
        │                         на метрику, по месяцам
        ▼
src/lib/metrics.ts              — единый источник правды: типы, чтение JSON,
                                   бизнес-логика (текущее значение, статус
                                   относительно цели), контент для
                                   hover-подсказок и методологии
        ▼
Компоненты (src/components/*)   — только отображение, вся логика уже
                                   посчитана в lib/metrics.ts
```

`lib/metrics.ts` — единственное место, которое знает про структуру
`mock-metrics.json`, разбивку метрик по разделам и порядок вывода. Компоненты
получают уже готовые типизированные объекты (`MetricDefinition`) и ничего не
вычисляют самостоятельно, кроме форматирования.

### Маршруты (App Router)

Все страницы статически генерируются (`generateStaticParams`) — рантайм-
бэкенда нет, всё собирается в статический HTML при `next build`.

| Маршрут | Назначение |
|---|---|
| `/` | Главный дашборд: 3 раздела × сетка карточек-метрик |
| `/metrics/[key]` | Детали метрики: крупный график, таблица значений по месяцам |
| `/metrics/[key]/methodology` | Методология расчёта: формула, источник данных, периодичность |

### Компоненты

- `src/components/ui/*` — низкоуровневые примитивы shadcn/ui (Card, Button,
  Chart, HoverCard, Badge, Separator) — не содержат бизнес-логики.
- `metric-line-chart.tsx` — линейный график (4 ряда), переиспользуется и на
  карточке, и на странице деталей.
- `target-badge.tsx` — бейдж «До цели: X» / «Опережаем цель на X».
- `metric-chart-card.tsx` — карточка метрики на главной: заголовок с
  hover-подсказкой (описание + ссылки на детали/методологию), значение,
  бейдж цели, график.
- `brand-logo.tsx`, `mode-toggle.tsx`, `print-button.tsx`,
  `theme-provider.tsx` — элементы шапки (лого, переключатель темы, экспорт
  в PDF).

### Тема и брендинг

Вся палитра и типографика — CSS-переменные в `src/app/globals.css`,
построенные на фирменной палитре X5 (`design_sources/pallete/`) и шрифтах
(`design_sources/fonts/` → `src/fonts/`). Тёмная тема — вариант по
умолчанию («futuristic control room»): почти чёрный фон, зелёное свечение,
карточки с glow-эффектом при наведении. Светлая тема использует ту же
систему токенов на светлом фоне. Отдельный `@media print` блок форсирует
светлую раскладку для PDF-экспорта независимо от активной темы.

Подробное обоснование решений по дизайну и данным — в [CLAUDE.md](./CLAUDE.md).
Полный каталог метрик, диапазоны mock-данных и разделы — в [METRICS.md](./METRICS.md).

## Структура проекта

```
src/
├── app/
│   ├── layout.tsx                          # шрифты, ThemeProvider
│   ├── page.tsx                            # главный дашборд
│   ├── globals.css                         # токены темы, палитра, print-стили
│   └── metrics/[key]/
│       ├── page.tsx                        # детали метрики
│       └── methodology/page.tsx            # методология метрики
├── components/
│   ├── ui/                                 # примитивы shadcn/ui
│   ├── metric-chart-card.tsx
│   ├── metric-line-chart.tsx
│   ├── target-badge.tsx
│   ├── brand-logo.tsx
│   ├── mode-toggle.tsx
│   ├── print-button.tsx
│   └── theme-provider.tsx
├── lib/
│   ├── metrics.ts                          # типы, доступ к данным, бизнес-логика
│   └── utils.ts                            # cn() — twMerge + clsx
└── fonts/                                  # фирменные шрифты X5 (.ttf)

data/
└── mock-metrics.json                       # сгенерированные данные метрик

design_sources/                             # исходники бренда (шрифты, палитра, лого)
```

## Быстрый старт

```bash
npm install
npm run dev       # http://localhost:3000
```

```bash
npm run build     # продакшн-сборка + статическая генерация всех маршрутов
npm run start     # запуск собранной версии
npm run lint
```

## Обновление данных

Значения метрик, диапазоны и цели живут в `data/mock-metrics.json`
(структура и логика генерации описаны в [METRICS.md](./METRICS.md#mock-данные)).
Тексты описаний и методологии — в `METRIC_CONTENT` внутри `src/lib/metrics.ts`.
Изменение любого из файлов не требует правок компонентов — вся вёрстка
читает данные через типизированные хелперы `lib/metrics.ts`.
